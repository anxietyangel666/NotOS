
  #### Причины медленной загрузки

  🔴 Критические — самые тяжёлые

  1. Аватары и обои хранятся как base64 data URL прямо в БД и передаются в каждом ответе
  Каждый PublicUser объект содержит avatarData (полная base64 строка изображения) и wallpaper. При загрузке мессенджера,
   списка друзей, участников группы — каждый пользователь тянет за собой свой аватар целиком. 50 друзей = 50 × ~100KB =
  ~5MB в одном JSON-ответе.

  2. pinnedCards хранятся в PublicUser и передаются везде
  Каждая закреплённая карточка содержит imageData — полный base64 видео или изображения (до 150MB). Это поле едет в
  каждом ответе где есть PublicUser, включая список участников группы.

  3. Хранилище (/api/storage) возвращает всё содержимое файлов сразу
  api.getStorage() возвращает StoragePayload со всеми файлами включая их content (base64). Файлы до 50MB. Это грузится
  при каждом открытии рабочего стола.

  4. Музыкальные треки хранятся в localStorage как base64
  getMusicTracks() читает из localStorage. При большом плейлисте это блокирует главный поток при старте.


-----------------------------------------------------------------------------------------------------------------------

  🟡 Средние — заметные тормоза

  5. Desktop.tsx — один монолитный компонент на 3000 строк
  Любое изменение состояния (движение мыши, таймер часов, уведомление) перерисовывает весь компонент. Нет React.memo,
  нет разбивки на подкомпоненты.

  6. Два параллельных Socket.IO соединения
  Desktop.tsx открывает свой сокет, MessengerWindow.tsx открывает свой. При открытом мессенджере работают два постоянных
   WebSocket соединения одновременно.

  7. DesktopWall открывает третий Socket.IO
  DesktopWall.tsx тоже создаёт io(API_URL) — итого три сокета одновременно.

  8. RemoteDesktopWindow — четвёртый сокет
  При просмотре чужого рабочего стола добавляется ещё один.

  9. Нет кэширования PublicUser профилей
  При каждом уведомлении о новом сообщении вызывается api.getPublicUser() заново — нет in-memory кэша.

  10. settingsDirty пересчитывается через JSON.stringify на каждый рендер

  JSON.stringify(nameplateDraft) !== JSON.stringify(user.nameplate ?? DEFAULT_NAMEPLATE)

  Это вызывается при каждом изменении любого состояния в Desktop.


-----------------------------------------------------------------------------------------------------------------------

  🟢 Мелкие — но накапливаются

  11. localStorage пишется при каждом изменении обоев
  useEffect на wallpaperDraft пишет в localStorage при каждом изменении, включая промежуточные состояния слайдера.

  12. saveWindowMaximized вызывается при каждом изменении любого из 9 окон
  Один useEffect с 9 зависимостями пишет в localStorage при любом изменении.

  13. Нет React.lazy / code splitting
  Все компоненты (AiChatWindow, RemoteDesktopWindow, GroupChatView и т.д.) импортируются синхронно в Desktop.tsx — весь
  бандл грузится сразу.
